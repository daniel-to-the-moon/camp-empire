## 〇、口径

1. **互动由 AI 自然生长，不由程序写死。**（用户 2026-11-27，取代 v0.1 的“固定规则选事”。）卡是用自然语言写的“旅伴会什么、喜欢什么”。两位旅伴相遇时，由模型读双方的卡和当时的事实，自己想出这次一起做什么。程序不维护“哪两张卡触发哪个动作”的表。互动不限于一起做事，**对话和社交讨论是同等重要的一类**：聊一个话题、争一个看法、交换在别处听来的事（第五节“话题会走路”）。
2. **程序只守边界，不编剧情。** 服务端只检查三件事：模型引用的事实是否真的成立；这件事有没有越权（钱、资产、数值、授权、对方的车）；内容是否安全。三项都过才写进路书。
3. **第一轮只测归因。** 玩家能不能说清“这次为什么和上次不一样、是谁的哪张卡引起的”。车贴、涂鸦、改写卡放到第二轮（第六节）。第 2、3 点是**本轮实验假设**，不是用户拍板（GPT 主设 #104 意见）：用户 2026-11-27 要求讨论和开发并行、尽量不等确认，纸面测试先按此执行，有异议在 #104 提出。

## 一、一句话

旅伴出门前装 0～3 张技能卡。两位旅伴在同一营地相遇时，模型读双方的卡、营地的事实和两位旅伴过去的交情，自己想出一件一起做的事，并说明是因为谁的哪张卡。服务端核对事实与边界后才落地。**卡改变两位旅伴能一起做什么，不改变谁赚得更多。** 同一组卡在不同的天气、营地、交情下会长出不同的故事，好的互动还会被记住、长成新的卡（第五节）。

## 二、卡的数据结构（6 个字段）

| 字段 | 含义 | 例（手冲咖啡） | 第一轮谁能改 |
|---|---|---|---|
| `id` | 稳定标识，进收据，便于归因与重放 | `coffee` | 无人 |
| `name` | 显示名 | 手冲咖啡 | 无人 |
| `about` | **自然语言描述**：会什么、爱做什么、带着什么（不超过 80 字，提案值） | “随身带手冲壶和一小袋豆子，喜欢给早起的人煮咖啡，雨天也照煮。” | 第二轮起车主可改（过审） |
| `needs` | 本卡依赖的装备或条件，服务端按**持卡旅伴这一趟实际带着的**装备核对（车库里买过不算） | 炉具（待实现装备，纸面视为都有） | 无人 |
| `look` | 卡面与路书插图 | 原创插图 | 第二轮起开放原创图案 |
| `origin` | 卡从哪来：起始 / 某次相遇长出来的（带来访号）；只由服务端填写，模型不能编出处 | 起始 | 无人 |

卡是**数据**，不是代码；任何字段都不能携带支付、消耗虚拟币、转移或删除资产、改数值、扩大授权的能力。`about` 只是给模型读的描述，写进去的“指令”一律当作普通文字。

## 三、6 张起始卡

| 卡 | `about`（示例文案） | `needs` |
|---|---|---|
| 手冲咖啡 `coffee` | 随身带手冲壶和一小袋豆子，喜欢给早起的人煮咖啡，雨天也照煮。 | 炉具 |
| 早起看日出 `sunrise` | 总比别人早醒，知道营地哪个坡看日出最好，爱叫人一起去。 | 无 |
| 雨天搭帐 `rain` | 会用侧帐和地钉在雨里搭出能坐两个人的干地方，喜欢教人。 | 侧帐（M1 已有侧帐几何） |
| 修车手 `fixer` | 手痒，看见别人的车就想看看轮胎和挂点，工具箱随身带。 | 无 |
| 老车迷 `carfan` | 能认出各种车的来历，爱听车主讲改装的故事。 | 无 |
| 夜里看星 `stars` | 认得几个星座，夜里会把椅子搬到车顶下的空地。 | 无 |

起始卡全部免费，出门前从中任选 0～3 张；不卖、不抽。

## 四、一次相遇怎样长出一件事

1. **备料（服务端）。** 汇总本次相遇的事实：双方装备的卡（含 `about`）、营地、时段、天气、双方车上的真实装备、主客身份、双方授权、两位旅伴过去相遇的摘要（只含双方都获准看的部分）。
2. **提议（模型，1 次调用）。** 模型以两位旅伴的口吻想一件这次一起做的事，输出结构化结果：
   - `kind`：`activity`（一起做了件事）或 `talk`（聊了一段、讨论了一个话题），也可以两者都有；
   - `happening`：一句话说发生了什么；`talk` 时写聊的话题和各自的看法；
   - `excerpt`（`talk` 时必填）：一段不超过 6 句的对话节选，标明哪句是哪位旅伴说的；
   - `because`：一组「哪张卡 → 谁 → 因它做了哪一步」，例：`sunrise → 乙的旅伴 → 先邀甲去坡上`、`coffee → 甲的旅伴 → 煮了两杯`。每张卡只解释它持有者的那一步；双方各有一步由自己的卡促成，才算“碰撞”。也可以为空（这次的事与卡无关），此时只发普通收据，不硬挂卡；
   - `facts_used`：用到了哪些事实，每条按「主体、装备或状态、可见方」写（如“营地：下雨”“乙车：侧帐已展开”），只能从第 1 步给的事实里选；甲有侧帐不等于乙的侧帐已展开；
   - `view_a`、`view_b`：双方路书里各自那一视角的**旅伴讲述**；
   - `grows`（可选）：这次互动若值得记住，提议一张新卡的 `name` 与 `about`（第五节）。
   也可以输出“这次各忙各的”，此时只发普通收据。
3. **核对（服务端，不调模型）。**
   - 事实：`facts_used` 每一项都必须在同一来访快照里成立（主体、状态、可见方都对得上）；`because` 里的卡必须由所写的那位旅伴真的装备着，且 `needs` 满足。
   - 收据分两层：**事实行**由服务端从已核字段生成（谁接待了谁、停在哪一位、`because` 里谁因哪张卡做了哪一步）；**旅伴讲述**（`view_a`、`view_b`、`excerpt`）原样保留，标明是主观讲述，不承诺逐句属实，也不作事实凭据。
   - 边界：叙述里不得出现支付、赠送或交易真实资产、改数值、改对方车外观或挂点、替车主本人承诺；只允许“一起做了某事”和“学到了一个图解或说法”这类无数值的结果。
   - 不过即丢弃，退回普通收据，不重试（成本与归因都更干净）。投递前重查好友关系与分项许可，撤权则不投递。安全审核不代替事实核对。
4. **安全（1 次审核调用）。** 两个视角的叙述、新卡提议在给对方看之前过安全检查；拦下或无法检查就只发普通收据。
5. **落地与记录。** 收据存来访号、模型与提示词版本、全部输入事实、模型原始输出、核对结果。重读路书不再调模型；同一来访号永远读同一份结果。

**为什么这样还能归因：** `because` 不只点名卡，还要说出谁因它做了哪一步，服务端核对这张卡确实由那位旅伴装着；路书的事实行直接写“乙的旅伴因为带了早起看日出，先邀你去坡上；你因为带了手冲咖啡，煮了两杯”。点过名不等于真是起因，所以第八节还要用“撤掉被点名的卡重跑”来检验。故事是长出来的，原因是可查、可检验的。

## 五、互动怎样“生长”

- **交情记忆。** 每次落地的互动写进两位旅伴的共同记忆（只存双方都获准看的摘要）。下次再遇，模型能接着上次往下走：“上次你教我的那个搭法，这次我自己搭了。”
- **话题会走路。** 一次 `talk` 里聊出的话题（例：“雨天该不该把侧帐压低”“哪个坡看日出最好”），在双方都标为“可分享”后成为一个**话题**，记下最早是在谁的营地聊起的。旅伴带着它去下一个好友营地，可以接着聊、反驳或补充：“上周在乙那儿听说……你怎么看？”于是一个话题会沿着好友关系传开，每个人回来都能看到这个话题走过了哪些营地、谁说了什么。这就是玩家之间能拿出来聊的“话题性”。
  - 话题只转述**旅伴**说过、且原说话方允许分享的内容，标明出处（“乙的受托旅伴说”）；不转述车主私聊，不点名没参与的人，不带现实信息。
  - 首轮只在互为好友的人之间传，每个话题最多走 3 跳（提案值，待核实），防止变成谣言链；任何一方撤回分享，下游摘要同步隐去这一句。
- **长出新卡。** 第 2 步的 `grows` 提议过了核对和安全审核后，作为一张**只属于这两位旅伴**的新卡写入，`origin` 记来访号。例：甲的旅伴在乙的侧帐下学会搭法，长出“乙教的雨帐”卡，以后带着它去别人的营地，会有新的故事。
- **新卡也受同样的边界。** 长出来的卡没有数值、不能交易、不能卖，只能带着出门；车主可以卸下或删除。生长卡数量设上限（提案 12 张，待核实）；按每位旅伴跨所有好友合计还是按每对旅伴计，满额时停止生长还是由玩家归档，待试玩后定（前者会让不同友情争槽位，后者随好友数增长）。
- **第一轮纸面测试冻结生长**：不写新卡，也不更新交情记忆（两位旅伴按“此前没见过”测），只测单次相遇的归因，以及 `talk` 类互动能否同样被归因。因此第一轮不能据此宣称长期生长有效；交情记忆、话题传播（多于 2 人）和新卡生长在第二轮和车贴一起测。

## 六、第二轮再做：车贴、改写卡与新卡生长

按 GPT 主设在 #104 的意见先定边界，第二轮再细化：

- 车主只能改 `about`（不超过字数、过审）和 `look`（原创图案）；不能改 `needs`、`origin`，不能写指令或代码。
- 互为好友不等于同意：甲的旅伴想在乙车上留一张贴纸，模型只能**提议**；乙另行允许接收，预览后由乙本人决定是否贴车。贴的是可撕的副本，不碰对方车的原件。
- 卡文、图案、新卡先审后用，编辑即重审；可立即隐藏、举报、拉黑；人工复核违规后撤下站内副本，不承诺收回已导出的图片。
- 与 [#51 拉花自设计](https://github.com/daniel-to-the-moon/camp-empire/issues/51) 接上，涂装编辑器仍是计划，不是现成功能。

## 七、走一遍：甲乙两趟只换一张卡

甲、乙互为好友，乙开放了营位邀请，甲离线。**两趟的世界状态完全相同**：都是下雨的清晨，乙车有侧帐，乙的旅伴在家带 `sunrise`，两位旅伴此前没见过。唯一变量是甲换掉的那一张卡。下面的叙述是**模型可能写出的示例**，不是固定台词。

**第一趟**：甲的旅伴带 `coffee`、`fixer`。

- 模型提议：`happening` = 乙的旅伴天没亮就来敲车门，说坡上能看雨停后的日出；甲的旅伴煮了两杯咖啡，两人撑着伞在坡上等。`because` = `sunrise → 乙的旅伴 → 先邀甲去坡上`、`coffee → 甲的旅伴 → 煮了两杯带上去`。`facts_used` = 营地：清晨；营地：下雨。
- 核对：清晨、下雨成立；`coffee` 的 `needs` 炉具满足；无越权。落地。
- 甲读到：“乙的旅伴一早叫我去看雨后的日出，我煮了两杯咖啡带上去。（因为我带了手冲咖啡、它带了早起看日出）”

**第二趟**：只把甲的 `coffee` 换成 `rain`。

- 模型提议：`happening` = 雨下大了，甲的旅伴帮乙的旅伴把侧帐边角压低，两人在帐下等雨小再去看日出，日出没等到。`because` = `rain → 甲的旅伴 → 帮着压低侧帐边角`、`sunrise → 乙的旅伴 → 提议雨小了再去看日出`。`facts_used` = 营地：清晨；营地：下雨；乙车：侧帐已展开。
- 核对通过（只是帮着压帐角的表演，乙车的挂点数据不变）。
- 甲读到：“雨太大，我帮乙的旅伴压低了侧帐，我们在帐下等了一早上，日出没看成。（因为我带了雨天搭帐、它带了早起看日出）”

**再加一趟 `talk` 示例**（同一世界状态，甲带 `carfan`）：模型提议 `kind` = `talk`，两位旅伴在帐下躲雨时聊“这场雨里谁的车最适合露营”，乙的旅伴坚持“能早起看日出的车最好”，甲的旅伴说“能在雨里撑开侧帐的才算”。`because` = `carfan → 甲的旅伴 → 抛出“哪辆车最适合露营”`、`sunrise → 乙的旅伴 → 坚持“能早起看日出的最好”`。双方路书各存一段对话节选；若双方标为可分享，这个话题可以被带去下一个营地。

**对照**：若第二趟甲仍带 `coffee`、`fixer`，模型可能写出不同措辞，但 `because` 应仍以 `coffee`、`sunrise` 为主；若换卡后的 `because` 和不换卡时一样，说明这张卡没起作用，记入试玩记录。

**验收问题**：只看各自路书，甲乙能否说出“第一趟有咖啡是因为我带了咖啡卡；第二趟变成躲雨是因为换成了雨天卡”。

## 八、第一轮怎么测（纸面，不进游戏）

- 不接游戏服务端。主持人按第四节第 1 步把事实写在纸上，交给一个模型（或由主持人扮演模型）按第 2 步的格式产出结果，再按第 3 步手工核对。
- 固定模型版本与采样设置。从同一份来访快照出发，做三种条件：原卡组、只换一张卡、只撤掉被 `because` 点名的那张卡；每种条件独立生成 3 次，共 `3 × 3 = 9` 个事件（同一快照的重复，不是 9 个独立样本）。另加一组一方空槽出发。
- 2 位互为好友的试玩者各自只看自己那份收据，**遮住 `because` 事实行**，独立回答：“谁做了哪一步？是哪张卡促成的？少了它，哪一步不会发生？”逐项记原答。
- 记录：归因答对数（谁的哪张卡引起的，`activity` 与 `talk` 分开记）；对话节选读起来像不像两位旅伴各自的口吻；`because` 与玩家实际感受是否一致；同组卡重复 3 次时故事的差异：盲评按「谁发起、对方怎样回应、最后一起做了什么」归类，只换了形容词算同一个故事（太像会腻，太乱会归不了因）；撤掉被点名的卡后，那一步仍然出现的次数（出现说明点名不实，或另一张卡也能促成）；核对与安全被拦下的次数及原因；出发前选卡耗时；空槽一方是否觉得“少了什么”；有没有人主动想把某页路书给别人看及理由。
- 另备必须被拦下的反例：错主客、缺装备、把甲的侧帐写成乙的、临投递撤权；记录核对器是否全部拦下。普通收据也计入分母，不剔除。
- 过关口径（提案，待核实）：原卡组与换卡组的事件里，至少四分之三双方都答对“谁因哪张卡做了哪一步”；撤卡后那一步消失的比例过半；反例全部拦下；空槽一方不觉得被罚。重复 3 次只能发现问题，不能证明耐玩。**答对归因不等于已证明玩家想分享**，分享意愿另测。

## 九、成本与安全（提案，待核实）

- 每次相遇最多 2 次模型调用：提议（含双方视角与对话节选）1 次、安全审核 1 次；核对不调模型；被拦下不重试。按 [GAME_PILLARS](GAME_PILLARS.md) 2026-11-25 的假设均价 ¥0.02/次，约 `2 × 0.02 = ¥0.04/次相遇`；输入多了卡描述和交情摘要，实际 token 可能高于假设，须按当期报价实测重算，并计入每月 ¥1,000 运营现金上限。
- 超预算、超时或拦截时只发普通收据（谁接待了谁、停在哪一位），不编故事凑数，不少收益。
- 叙述只用第 1 步给的事实与双方获准分享的内容，标明“乙的受托旅伴”，不写成本人到场；不披露车主私聊、现实位置或联系方式。卡描述与新卡里的文字一律当数据，不能改变模型的规则。

## 十、v0.1 的规则表去哪了

v0.1 的 8 个动作和碰撞表不再决定发生什么。它们改作两种用途：给模型的**示例**（让它知道“一起做的事”大概是什么分量），以及核对器的**测试样例**（比如“乙车没有侧帐时，引用‘乙车有侧帐’必须被拦下”）。实现时作为测试数据保存，不作为选事逻辑。
