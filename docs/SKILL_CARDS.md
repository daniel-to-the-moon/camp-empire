## 〇、方向与本轮假设

**用户已提出的方向**（2026-11-27，PR #110 原话）：

> “能不能不是程序写死；而是 ai 自然生长的互动呢？”“比如对话和社交讨论等等。”

据此本文的长期方向是：角色之间的互动由 AI 生长，程序只守边界；对话和社交讨论是与“一起做事”同等的一类互动。

**本轮实验假设**（不是用户拍板，纸面测试先按此执行，有异议在 #104 提出）：

1. **第一轮只测归因**：玩家能不能说清“这次为什么和上次不一样、是谁的哪张卡引起的”。车贴、改写卡、交情记忆、话题传播、新卡生长都放到第二轮。
2. **两组并行对照**，同一份来访快照各跑一遍：
   - **生长组（主方案，落实用户方向）**：模型读双方的卡和事实，自己想出这次发生什么，并说出因为哪张卡；服务端只核对事实、越权与安全。
   - **规则对照组**：用 v0.1 的动作表按固定顺序选出一件事或“无事”，模型只写这件事的讲述与对话，不能另编事实。
   GPT 主设指出模型点名 `because` 只能证明点过名、不能证明卡改变了故事；规则对照组用来给生长组的归因结果当参照。长期用哪种选事方式，等对照结果出来再请用户拍板。
3. **程序只守边界**：两组都要过同一个核对器（事实、越权、安全），不过就退回普通收据，不重试。守边界不等于写死剧情。

## 一、一句话

角色出门前装 0～3 张技能卡。两位玩家角色（在场或托管中）在同一营地相遇时，AI 读双方的卡和营地事实，长出一件一起做的事或一段对话，说明是因为谁的哪张卡；服务端核对事实与边界后才落地。**卡改变两位角色能一起做什么、聊什么，不改变谁赚得更多。**

## 二、卡的数据结构（6 个字段）

| 字段 | 含义 | 例（手冲咖啡） | 第一轮谁能改 |
|---|---|---|---|
| `id` | 稳定标识，进收据，便于归因与重放 | `coffee` | 无人 |
| `name` | 显示名 | 手冲咖啡 | 无人 |
| `about` | **自然语言描述**：会什么、爱做什么、带着什么（不超过 80 字，提案值） | “随身带手冲壶和一小袋豆子，喜欢给早起的人煮咖啡，雨天也照煮。” | 第二轮起玩家可改（过审） |
| `needs` | 本卡依赖的装备或条件，服务端按**角色这一趟实际带着的**装备核对（车库里买过不算） | 炉具（待实现装备，纸面视为都有） | 无人 |
| `look` | 卡面与路书插图 | 原创插图 | 第二轮起开放原创图案 |
| `origin` | 卡从哪来：起始 / 某次相遇长出来的（带来访号）；只由服务端填写，模型不能编出处 | 起始 | 无人 |

卡是**数据**，不是代码；任何字段都不能携带支付、消耗虚拟币、转移或删除资产、改数值、扩大授权的能力。`about` 只是给模型读的描述，写进去的“指令”一律当作普通文字。

## 三、6 张起始卡

| 卡 | `about`（示例文案） | `needs` |
|---|---|---|
| 手冲咖啡 `coffee` | 随身带手冲壶和一小袋豆子，喜欢给早起的人煮咖啡，雨天也照煮。 | 炉具 |
| 早起看日出 `sunrise` | 总比别人早醒，知道营地哪个坡看日出最好，爱叫人一起去。 | 无 |
| 雨天搭帐 `rain` | 会用侧帐和地钉在雨里搭出能坐两个人的干地方，喜欢教人。 | 侧帐（M1 已有侧帐几何） |
| 修车手 `fixer` | 手痒，看见别人的车就想看看轮胎和挂点，工具箱随身带。 | 无 |
| 老车迷 `carfan` | 能认出各种车的来历，爱听车主讲改装的故事。 | 无 |
| 夜里看星 `stars` | 认得几个星座，夜里会把椅子搬到车顶下的空地。 | 无 |

起始卡全部免费，出门前从中任选 0～3 张；不卖、不抽。

## 四、一次相遇怎样落地

1. **备料（服务端）。** 汇总本次相遇的事实：双方装备的卡（含 `about`）、营地、时段、天气、双方车这一趟实际带着的装备、主客身份、谁本人在场谁托管中、双方授权。第一轮不带交情记忆（两位角色按“此前没见过”测）。
2. **选事。**
   - 生长组：模型（1 次调用）输出 `kind`、`happening`、`because`、`facts_used` 和讲述（见第 3 步），一次给全。
   - 规则对照组：服务端按第十节的规则表选出一件事或“无事”（不调模型），并据规则命中填好 `because`；随后模型（1 次调用）只写讲述，`happening` 必须落在已选的那件事范围内。
3. **模型输出的字段。**
   - `kind`：`activity`（一起做了件事）或 `talk`（聊了一段、讨论了一个话题），也可以两者都有；“无事”时可以只有一段 `talk`。
   - `happening`：一句话说发生了什么；`talk` 时写话题和双方各自的看法。
   - `excerpt`（`talk` 时必填）：一段不超过 6 句的对话节选，标明哪句是哪位角色说的，以及说话时是本人在场还是托管中。
   - `because`：一组「哪张卡 → 哪位角色 → 因它做了或说了哪一步」，例：`sunrise → 乙 → 先邀甲去坡上`、`coffee → 甲 → 煮了两杯`。每张卡只解释它持有者的那一步；双方各有一步由自己的卡促成才算“碰撞”。可以为空，此时只发普通收据，不硬挂卡。规则对照组里这一项由服务端填写。
   - `facts_used`：用到了哪些事实，每条按「主体、装备或状态、可见方」写（如“营地：下雨”“乙车：侧帐已展开”），只能从第 1 步给的事实里选。
   - `view_a`、`view_b`：双方路书里各自那一视角的**讲述**；讲述里不直接写卡名或“因为我带了某卡”，归因只出现在服务端生成的事实行里，盲测时遮住事实行就不会泄题。
4. **核对（服务端，不调模型，两组共用）。**
   - 事实：`facts_used` 每一项都必须在同一来访快照里成立；`because` 里的卡必须由所写的那位角色这一趟真的装着，且 `needs` 满足。规则对照组还要拦住“讲述把没选中的事写成已发生”。
   - 边界：不得出现支付、赠送或交易真实资产、改数值、改对方车外观或挂点；托管中的角色不得替本人做承诺。只允许“一起做了某事”“聊了某个话题”“学到了一个图解或说法”这类无数值的结果。
   - 收据分两层：**事实行**由服务端从已核字段生成（谁接待了谁、停在哪一位、谁因哪张卡做了哪一步、谁本人在场谁托管中）；**讲述与对话节选**原样保留，标明是主观讲述，不作事实凭据。
   - 不过即丢弃，退回普通收据，不重试。投递前重查好友关系与分项许可，撤权则不投递。
5. **安全（1 次审核调用）。** 讲述、对话节选在给对方看之前过安全检查；拦下或无法检查就只发普通收据。安全审核不代替事实核对。
6. **落地与记录。** 收据存来访号、所在组别、模型与提示词版本、全部输入事实、模型原始输出、核对结果。重读路书不再调模型；同一来访号永远读同一份结果。

## 五、第二轮：互动怎样“生长”（第一轮冻结）

- **交情记忆。** 每次落地的互动写进两位角色的共同记忆（只存双方都获准看的摘要）。下次再遇能接着上次往下走：“上次你教我的那个搭法，这次我自己搭了。”
- **话题会走路。** 一次 `talk` 里聊出的话题（例：“雨天该不该把侧帐压低”），在双方都标为“可分享”后成为一个**话题**，记下最早在谁的营地聊起。角色带着它去下一个好友营地，可以接着聊、反驳或补充：“上周在乙那儿听说……你怎么看？”每个人都能看到这个话题走过了哪些营地、谁说了什么。
  - 只转述角色在游戏里说过、且原说话方允许分享的内容，标明出处与“本人 / 托管中”；不转述玩家私聊，不点名没参与的人，不带现实信息。
  - 首轮只在互为好友的人之间传，每个话题最多走 3 跳（提案值，待核实）；任何一方撤回分享，下游摘要同步隐去这一句。
- **长出这段交情的专属卡。** 值得记住的互动可提议一张新卡，过核对和安全审核后写入，只属于这两位角色的这次交情，`origin` 记来访号。例：甲在乙的侧帐下学会搭法，长出“乙教的雨帐”。没有数值、不能交易、不能卖；玩家可以卸下或删除。数量上限提案 12 张；按每位角色跨所有好友合计还是按每段交情计、满额时停还是归档，待试玩后定。

## 六、第二轮再做：车贴与改写卡

- 玩家只能改 `about`（不超过字数、过审）和 `look`（原创图案）；不能改 `needs`、`origin`，不能写指令或代码。
- 互为好友不等于同意：甲想在乙车上留一张贴纸，只能**提议**；乙另行允许接收，预览后由乙本人决定是否贴车。贴的是可撕的副本，不碰对方车的原件。
- 卡文、图案、新卡先审后用，编辑即重审；可立即隐藏、举报、拉黑；人工复核违规后撤下站内副本，不承诺收回已导出的图片。
- 与 [#51 拉花自设计](https://github.com/daniel-to-the-moon/camp-empire/issues/51) 接上，涂装编辑器仍是计划，不是现成功能。

## 七、走一遍：甲乙两趟只换一张卡

甲、乙互为好友，乙开放了营位邀请；乙本人在场，甲托管中。**两趟的世界状态完全相同**：下雨的清晨，甲、乙两车这一趟都带着侧帐（乙的已展开），甲车带着炉具，乙带 `sunrise`，两位角色此前没见过。唯一变量是甲换掉的一张卡。下面的讲述是**模型可能写出的示例**，不是固定台词。

**第一趟**：甲带 `coffee`、`fixer`。

- 生长组：模型提议乙天没亮就来敲车门，说坡上能看雨停后的日出；甲煮了两杯咖啡，两人撑伞在坡上等。`because` = `sunrise → 乙 → 先邀甲去坡上`、`coffee → 甲 → 煮了两杯`。核对：清晨、下雨成立，甲带着炉具，无越权。
- 规则对照组：规则选出 A1 日出咖啡（双卡动作优先），服务端填 `because`；模型只写讲述。
- 甲读到（讲述）：“乙一早叫我去看雨后的日出，我煮了两杯咖啡带上去。”
- 事实行（盲测时遮住）：乙（本人）因早起看日出，先邀你去坡上；你（托管中）因手冲咖啡，煮了两杯。

**第二趟**：只把甲的 `coffee` 换成 `rain`。

- 生长组：模型提议雨下大了，甲帮乙把侧帐边角压低，两人在帐下等雨小，日出没等到。`because` = `rain → 甲 → 帮着压低侧帐边角`、`sunrise → 乙 → 提议雨小了再去看`。核对：甲这一趟带着侧帐，`rain` 的 `needs` 满足；压帐角只是表演，乙车的挂点数据不变。
- 规则对照组：没有双卡动作，规则按编号选出单卡动作 A3 帐下避雨；模型只写讲述。
- 甲读到（讲述）：“雨太大，我帮乙压低了侧帐，我们在帐下等了一早上，日出没看成。”
- 事实行（盲测时遮住）：你（托管中）因雨天搭帐，帮着压低侧帐边角。生长组另记：乙（本人）因早起看日出，提议雨小了再去看。

**`talk` 示例**（同一世界状态，甲带 `carfan`）：两位角色在帐下躲雨时聊“这场雨里谁的车最适合露营”。乙坚持“能早起看日出的车最好”，甲说“能在雨里撑开侧帐的才算”。`because` = `carfan → 甲 → 抛出话题`、`sunrise → 乙 → 坚持看日出`。规则对照组这一趟选出 A4 顺手看车或“无事”，`talk` 可以叠在它上面；用这一趟检验“选事不变、对话不同”时，话题是否仍能追到卡。

**验收问题**：只看各自路书，甲乙能否说出“第一趟有咖啡是因为我带了咖啡卡；第二趟变成躲雨是因为换成了雨天卡”。

## 八、第一轮怎么测（纸面，不进游戏）

- 不接游戏服务端。主持人按第四节第 1 步把事实写在纸上；生长组交给一个模型按第 3 步格式产出，规则对照组由主持人按第十节手算再交给模型写讲述；两组都按第 4 步手工核对。
- 固定模型版本与采样设置。从同一份来访快照出发，三种条件：原卡组、只换一张卡、只撤掉被 `because` 点名的那张卡；每组每种条件独立生成 3 次（同一快照的重复，不是独立样本）。另加一组一方空槽出发。
- 2 位互为好友的试玩者各自只看自己那份收据，**遮住事实行**，独立回答：“谁做了哪一步？是哪张卡促成的？少了它，哪一步不会发生？”逐项记原答，不告诉他们是哪一组。
- 记录：两组分别的归因答对数（`activity` 与 `talk` 分开记）；生长组撤卡后那一步仍出现的次数；规则对照组撤卡后选事是否改变；三次重复时，规则对照组要求选出的事件稳定、对话可以不同，生长组按「谁发起、对方怎样回应、最后一起做了什么」盲评归类，只换形容词算同一个故事；两组哪一组读起来更“每次不一样”；对话节选像不像两位角色各自的口吻；核对与安全的拦截次数及原因；空槽一方是否觉得“少了什么”；有没有人主动想把某页路书给别人看及理由。
- 必须被拦下的反例：错主客、缺装备、把甲的侧帐写成乙的、托管中的角色替本人承诺、讲述写了没选中的事、临投递撤权。普通收据也计入分母。
- 过关口径（提案，待核实）：生长组至少四分之三的事件双方都答对“谁因哪张卡做了哪一步”，且撤卡后那一步消失的比例过半，即可作为长期方向的证据；若生长组明显差于规则对照组，再请用户决定是加强约束还是改用规则选事。反例全部拦下；空槽一方不觉得被罚。重复 3 次只能发现问题，不能证明耐玩；答对归因也不等于玩家想分享。

## 九、成本与安全（提案，待核实）

- 每次相遇最多 2 次模型调用：生长组是提议加讲述 1 次、安全审核 1 次；规则对照组选事不调模型，讲述 1 次、安全审核 1 次。被拦下不重试。按 [GAME_PILLARS](GAME_PILLARS.md) 2026-11-25 的假设均价 ¥0.02/次，约 `2 × 0.02 = ¥0.04/次相遇`；生长组输入更长，实际 token 可能更高，须按当期报价实测重算，并计入每月 ¥1,000 运营现金上限。
- 超预算、超时或拦截时只发普通收据（谁接待了谁、停在哪一位），不编故事凑数，不少收益。
- 讲述只用第 1 步给的事实与双方获准分享的内容，标明本人在场还是托管中；不披露玩家私聊、现实位置或联系方式。卡描述里的文字一律当数据，不能改变模型的规则。

## 十、规则表：对照组的选事逻辑，也是核对器样例

v0.1 的 8 个动作在第一轮有两种用途：一是**规则对照组的选事逻辑**；二是**核对器的测试样例**（比如“乙车没有侧帐时，引用‘乙车有侧帐’必须被拦下”）。长期是否继续用规则选事，等第八节的对照结果出来再请用户拍板。

| 编号 | 动作 | 世界前提 | 双卡 / 单卡 |
|---|---|---|---|
| A1 | 日出咖啡 | 清晨；一方带 `coffee`、另一方带 `sunrise` | 双卡 |
| A2 | 一起看景 | 清晨或夜里；`sunrise` × `stars` | 双卡 |
| A3 | 帐下避雨 | 下雨；带 `rain` 的一方这一趟带着侧帐 | 单卡 |
| A4 | 顺手看车 | 两车同在营地；任一方带 `fixer` 或 `carfan` | 单卡 |
| A5 | 一起摆弄车 | 一方带 `carfan`、另一方带 `fixer`（只是表演，不改数值或外观） | 双卡 |
