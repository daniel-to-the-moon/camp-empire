## 〇、本轮已定的两点

用户 2026-11-27 要求“讨论和开发并行、尽量不等确认”，以下两点按 GPT 主设在 #104 的建议先定，作为第一轮打样口径；有异议在 #104 提出，改口径只需改本文：

1. **第一轮只测归因**：玩家能不能说清“这次为什么和上次不一样、是谁的哪张卡引起的”。车贴、涂鸦、改写卡放到第二轮（第六节）。
2. **固定规则选事**：碰撞结果由规则算出合法候选并按固定顺序选第一项；模型只能**接受或谢绝**这一项，不能另选、不能新增。模型在多个候选里自选的玩法留到归因测通之后再评估。

## 一、一句话

旅伴出门前装 0～3 张技能卡。两位旅伴在同一营地相遇时，服务端拿双方的卡和当时的事实（时间、天气、装备、授权）对规则表，最多落一件“一起做的事”；模型只把已经发生的事讲进双方路书。**卡改变两位旅伴能一起做什么，不改变谁赚得更多。**

## 二、卡的数据结构（8 个字段）

| 字段 | 含义 | 例（手冲咖啡） | 第一轮谁能改 |
|---|---|---|---|
| `id` | 稳定标识，进收据，便于重放 | `coffee` | 无人 |
| `name` | 显示名 | 手冲咖啡 | 无人 |
| `tags` | 供规则匹配的标签 | `drink`、`morning`、`host` | 无人 |
| `requires` | 本卡自身的前提（装备、时段） | 车上有炉具 | 无人 |
| `effects` | 可触发的动作引用（第三节动作表的编号） | `A1`、`A6` | 无人 |
| `prefs` | 白名单内的偏好，只影响叙述语气，不影响是否触发 | 口味：浅烘 / 深烘 | 车主（第二轮起） |
| `look` | 卡面与路书插图 | 原创插图 | 第二轮起开放原创图案 |
| `expires` | 有效期；过期自动卸下，不扣东西 | 本趟出行结束 | 无人 |

约束（提案）：卡是**数据**，不是代码；任何字段都不能携带支付、消耗虚拟币、转移资产、删除资产或扩大授权的能力。

## 三、6 张起始卡与 8 个动作

### 起始卡（全部免费，出门前从中任选 0～3 张）

| 卡 | `tags` | 自身前提 | 能触发的动作 |
|---|---|---|---|
| 手冲咖啡 `coffee` | drink、morning、host | 车上有炉具（待实现装备，第一轮纸面视为都有） | A1、A6 |
| 早起看日出 `sunrise` | morning、view | 无 | A1、A2 |
| 雨天搭帐 `rain` | weather、shelter | 车上有侧帐（M1 已有侧帐几何，`src/shared/config.ts` 的 `awningGapFactor`） | A3、A7 |
| 修车手 `fixer` | tools、help | 无 | A4、A5、A7 |
| 老车迷 `carfan` | vehicle、talk | 无 | A5、A4 |
| 夜里看星 `stars` | night、view | 无 | A8、A2 |

### 动作表（服务端确认后才算发生）

| 编号 | 动作 | 世界前提（全部满足才是合法候选） | 双方路书记下什么 |
|---|---|---|---|
| A1 | 日出咖啡 | 清晨时段；一方带 `coffee`、另一方带 `sunrise` | 谁叫醒谁、谁煮了咖啡 |
| A2 | 一起看景 | 清晨或夜里；双方都带 `view` 标签的卡（`sunrise` × `stars`） | 看了什么、在哪个营地 |
| A3 | 帐下避雨 | 下雨；营地内至少一方车有侧帐；一方带 `rain` | 谁的侧帐、谁在帐下 |
| A4 | 顺手看车 | 两车同在营地；任一方带 `fixer` 或 `carfan` | 看了哪辆车的哪个部位；**不改任何数值或外观** |
| A5 | 一起摆弄车 | 一方带 `carfan`、另一方带 `fixer` | 谁讲车、谁动手（只是表演，不改任何数值或外观） |
| A6 | 请喝一杯 | 一方带 `host` 标签的卡，且是营主或营主的受托旅伴 | 谁招待了谁 |
| A7 | 教搭法 | 下雨或刚下过；一方带 `rain`、另一方带 `fixer` | 谁教了谁一个搭法的**图解**（不替对方改挂点） |
| A8 | 夜里看星 | 夜里；任一方带 `stars` | 谁在谁的营地看了星 |

没有任何合法候选时，相遇照常完成：双方仍收到“谁接待了谁、停在哪一位”的收据，不少收益、不催补卡。

## 四、规则怎样选出“这一件事”

1. **只比跨方卡。** 甲最多 3 张、乙最多 3 张，最多 `3 × 3 = 9` 次跨方配对；同一方自己的卡不互相配对。
2. **生成候选。** 对每次配对，查动作表里两张卡都“能触发”且世界前提全部满足的双卡动作；单张卡就能触发的单卡动作（A3、A4、A6、A8）也进候选。重复的动作合并为一条。
3. **固定顺序选第一项。** 先选双卡动作（A1、A2、A5、A7），再选单卡动作（A3、A4、A6、A8）；同一层内按动作表编号升序。双卡动作必须排在前面：A5、A7 成立时，A4（以及雨天的 A3）几乎总同时成立，若只按编号排，A5、A7 永远选不到（Codex 审核 #110）。排序只依赖动作编号，同一来访号重放得到同一结果。第一轮只取第一项。
4. **服务端复核再提交。** 提交前重查邀请、好友关系、装备、双方授权与时段；任一项不再成立就退到下一候选，全部不成立就记“无共同行动”。
5. **模型只能接受或谢绝。** 模型拿到选中的动作和事实，回答“接受”并写叙述，或“谢绝”并给一句理由；谢绝即记“无共同行动”，不换下一项（第一轮便于归因）。
6. **记录**：收据存来访号、规则版本、双方装备的卡、选中的动作、模型是否谢绝。重读路书不再调模型、不重新选事。

## 五、碰撞表

### 6 张卡两两组合（`6 × 5 ÷ 2 = 15` 对）

“—”表示这对卡本身碰不出双卡动作，只剩单卡动作或什么都不发生；**什么都不发生也没关系**，收据照发。条件指第三节的世界前提。

|---|---|---|---|---|---|---|
| **coffee** | 同卡（见下） | A1（清晨） | — | — | — | — |
| **sunrise** | | 同卡 | — | — | — | A2（清晨或夜里） |
| **rain** | | | 同卡 | A7（雨） | — | — |
| **fixer** | | | | 同卡 | A5 | — |
| **carfan** | | | | | 同卡 | — |
| **stars** | | | | | | 同卡 |

（双卡动作只有 A1、A2、A5、A7 四个；A3、A4、A6、A8 是单卡动作，任何组合里只要单方满足就进候选。上表只列这对卡**一起**才碰出的动作。）

### 15 对之外必须测的情况

| 情况 | 期望结果 |
|---|---|
| 同卡（双方都带 `coffee`） | 不额外触发；按单卡动作处理（如 A6） |
| 双卡动作压过单卡（甲带 fixer、乙带 carfan，同在营地） | 选 A5，不选 A4；雨天甲带 rain、乙带 fixer 时选 A7，不选 A3、A4 |
| 主客互换（甲去乙家 vs 乙来甲家） | A6“请喝一杯”只给营主一方；其余动作与主客无关 |
| 多项命中（如雨天清晨，甲带 coffee＋rain、乙带 sunrise＋fixer） | 双卡动作 A1、A7 先于单卡 A3、A4，再按编号取 A1；收据记下其余候选编号，便于试玩后复盘 |
| 空槽（一方 0 张卡） | 可出发；只剩对方单卡动作或无共同行动，收据照发 |
| 投递前撤权（乙中途撤回接待许可） | 服务端复核不过，记“无共同行动”，不投递叙述 |
| 模型谢绝 | 记“无共同行动”，收据写明“乙的旅伴这次没有一起做” |

## 七、走一遍：甲乙两趟只换一张卡

甲、乙互为好友，乙在线时开放了营位邀请，甲离线。

**第一趟**：甲的旅伴带 `coffee`、`fixer` 出门；乙的旅伴在家带 `sunrise`。甲的旅伴清晨到乙营地。候选：A1 日出咖啡（`coffee` × `sunrise`，清晨成立）、A4 顺手看车（甲带 `fixer`）；A6 不成立（甲是访客）。双卡动作 A1 优先，选 A1，模型接受。

- 甲回来读到：“我在乙的营地停在 2 号位。乙的旅伴一早叫醒我，我煮了两杯咖啡，一起等日出。”
- 乙读到同一次来访的另一视角：“甲的旅伴停在 2 号位。我叫它起来看日出，它给我煮了咖啡。”

**第二趟**：只把甲的 `coffee` 换成 `rain`；那天午后下雨，乙仍带 `sunrise`。跨方配对 `rain` × `sunrise`、`fixer` × `sunrise` 都碰不出双卡动作（`rain` 与 `fixer` 同属甲，不配对，所以没有 A7）；单卡候选：A3 帐下避雨（下雨、乙车有侧帐、甲带 `rain`）、A4 顺手看车。按编号选 A3。

- 甲读到：“下雨了，我躲在乙的侧帐下。”乙读到：“甲的旅伴在我侧帐下避雨。”

**验收问题**：只看各自路书，甲乙能否说出“第一趟有咖啡是因为我带了咖啡卡、你在等日出；第二趟变成避雨是因为换了雨天卡、又刚好下雨”。

## 八、第一轮怎么测（纸面，不调模型）

- 规则表打印成纸，主持人按第四节手工算结果，叙述用预写模板，**零模型调用**。
- 2 位互为好友的试玩者，错峰各走两趟，每趟只换一张卡；另设一组对照：一方空槽出发。
- 记录：归因答对数（谁的哪张卡引起的）、出发前选卡耗时、空槽一方是否觉得“少了什么”、有没有人主动想把某页路书给别人看及理由。
- 过关口径（提案，待核实）：4 趟里至少 3 趟双方都答对归因；空槽一方不觉得被罚。**答对归因不等于已证明玩家想分享**，分享意愿另测。

## 九、成本与安全（提案，待核实）

- 上线后每次相遇双方合计最多 3 次模型调用：接受/谢绝并写叙述 1 次、第二视角叙述 1 次、出站审核 1 次，不重试。按 [GAME_PILLARS](GAME_PILLARS.md) 2026-11-25 的假设均价 ¥0.02/次，约 `3 × 0.02 = ¥0.06/次相遇`；不是报价，须按当期报价与实测 token 重算，并计入每月 ¥1,000 运营现金上限。
- 超预算、超时或审核失败时只留预审过的模板收据，不编故事凑数。
- 叙述只用本次已确认的事实与双方获准分享的内容，标明“乙的受托旅伴”，不写成本人到场；不披露车主私聊、现实位置或联系方式。
